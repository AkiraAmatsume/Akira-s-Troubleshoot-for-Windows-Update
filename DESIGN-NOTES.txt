Akira's Troubleshoot for Windows Update — 设计约束说明
======================================================

本文档记录本工具在运行时平台上的技术约束及其依据。
面向最终用户的完整说明见 release/README.md；本文档仅阐述平台选型的决策依据与维护约束。

目标读者：维护本项目的开发者。


1. 适用平台
-----------
本程序固定采用以下运行时平台：

  - 目标框架：.NET Framework 4.8
  - 进程架构：x86（32 位）

以上两项均由构建配置强制保证（见第 5 节），不属于可协商的实现细节。


2. 运行环境假设
---------------
本工具仅在 Windows Update 已失效时被运行，其运行环境并非健康的操作系统，
而是可能已被精简、优化或更新禁用类工具破坏的系统。

由此导出的设计前提为：

    运行环境的最低保证优先于实现简洁性。

该前提是本文档其余各项决策的依据。


3. .NET Framework 4.8 的选择依据
--------------------------------
  - .NET Framework 4.8 为 Windows 10（1903 起）与 Windows 11 的内置组件，
    随系统分发，不会被精简工具作为独立运行时而移除。
  - .NET Core / .NET 5+ / AOT 独立部署需要额外运行时（如 WindowsAppRuntime），
    此类组件是精简/优化工具的常见删除目标；一旦缺失，程序无法启动。
  - 依赖内置运行时使本工具无需安装、无额外依赖，符合应急修复工具的定位：
    其依赖应为被破坏系统中仍然存在的组件，而非可能一并受损的新运行时。


4. x86 的选择依据
-----------------
  - x86 进程可在 32 位与 64 位系统上启动；x64 进程无法在 32 位系统上启动。
  - 本工具的支持范围为 Windows 10 / 11（当前以 64 位为主），保留 x86
    可换取在更多（含被改造过的）系统上的启动能力。
  - x64 本身在技术上更优，但对“故障系统修复”这一目标场景无实质收益，
    反而缩小了可启动的范围。

结论：启动成功率优先于实现简洁性。


5. 构建约束（强制项）
---------------------
构建配置必须满足以下条件，否则上述前提将失效且不会产生编译错误：

  - WindowsUpdateFixer.csproj 中必须显式声明 <PlatformTarget>x86</PlatformTarget>。
    若仅设置 Platform=AnyCPU 而未声明 PlatformTarget，产物在 64 位系统上将以
    x64 运行，从而绕过本工具依赖的 x86 前提。
  - 必须设置 <Prefer32Bit>false</Prefer32Bit>。
  - TargetFrameworkVersion 必须为 v4.8。

验证方式：构建后检查产物的 PE 头，Machine 字段应为 I386（0x014C），
且 ILONLY 位应为 0（即 x86 特定架构，而非 AnyCPU）。


6. 构建产物的处理（强制项）
---------------------------
构建会在 code/ 下生成 bin/ 与 obj/ 两个目录。二者均为构建产物，不属于源码，
且已列入 .gitignore。维护者须遵守以下约定：

  - 构建完成后，主动清理 code/bin 与 code/obj，避免构建产物滞留于源码目录。
  - 正式发布的程序文件统一存放于仓库根目录的 release/ 文件夹，
    而非 code/bin 之下。不得将 code/ 中的临时产物直接作为发布件分发。
  - 发布流程：以 Release 配置构建 → 将产出的 exe 复制到 release/ →
    清理 code/bin 与 code/obj。


7. x86 带来的已知代价
---------------------
选择 x86 会引入 WOW64 相关行为差异，相关处理集中于 Services/SystemCompat.cs，
以及需要读取服务/注册表配置的模块。以下特判为本前提的必要代价，不应删除：

  - 文件系统重定向：x86 进程访问 System32 时被重定向至 SysWOW64。
    处理：SystemCompat.RawSystem32() 由 SysWOW64 的父目录推导真实 System32。
  - 注册表视图重定向：RegistryView.Default 被重定向至 WOW6432Node，
    其中 ProductName / EditionID 等与真实值不同。
    处理：读取服务配置与系统版本时显式指定 64/32 位视图。
  - Environment.OSVersion 兼容值：x86 进程中可能返回 6.2.9200 等兼容值，不可信。
    处理：版本判断以注册表 CurrentBuild 为准。

只要本工具仍采用 x86，上述特判即为必要实现，不属于可清理的冗余。


8. 重新评估的前提条件
---------------------
仅在以下任一条件成立时，方考虑调整本决策：

  - 明确放弃对 32 位运行环境的兼容，且确认目标系统在被破坏后仍保证存在
    可用的更新版 .NET 运行时。
  - 产品定位由“故障系统应急修复”变更为“面向健康系统的通用工具”。

在上述前提未变更前，不应将本程序改为 x64，或迁移至更新的 .NET 版本。
